# keeptip-content 的实现（微信 4.2.0 / 构建号 270416 / arm64）

## 为什么只改字节做不到

撤回解析函数的产物只有两样：删哪条（`+0x1c8`）和提示文案（`+0x1d0`）。文案直接来自服务端 XML 的
`replacemsg`，原消息正文不在其中。要在提示里显示原文，必须有新代码：收到消息时记下摘要，撤回时改写提示。

## 补丁点

原始 arm64 切片 SHA-256：`9e437ad6b0ff077137655058a318cee417cb32926e3a8b19be81714d816c3f48`

| 地址 | 内容 |
|---|---|
| `0x4667638` | `str x0` → `str xzr`，把 `newmsgid` 清零（即 `keeptip`） |
| `0x2db8` | 在 Mach-O 头部空白区追加 `LC_LOAD_WEAK_DYLIB @loader_path/libwxar_tip.dylib` |
| `0x10` | `ncmds` 99 → 100，`sizeofcmds` 0x2d98 → 0x2dd0 |
| `0x16e00` | 头部空白区里的两段小桩 |
| `0x4666ba4` | 解析函数 `0x4666c28` 的唯一调用点，改为 `bl` 桩 1 |
| `0x4612e90` | Message 终结器入口，改为 `b` 桩 2 |

全部是等长替换，由 `runtime/gen_patch.py` 生成。写入顺序是 桩 → load command → 头 → 跳转，中途中断也不会留下畸形的头。

桩从 `0x9e27f00 / 0x9e27f08` 取函数指针，为 0 就走原逻辑，所以模块缺失时等同 `keeptip`：

```
adrp x16, slot@PAGE
ldr  x16, [x16, slot@PAGEOFF]
cbz  x16, 1f
br   x16
1:   原逻辑
```

这两个槽在 `__DATA` 末尾的零填充空洞里：最后的 `__common` 止于 `0x9e24c68`，段到 `0x9e28000`。
不需要可执行内存，运行时也不改代码。

## 结构体字段

| 对象 | 偏移 | 含义 | 代码依据 |
|---|---|---|---|
| Message | `+0x0C` / `+0x10` | 类型 / 子类型 | `0x4612884` |
| Message | `+0x48` | 发送者 | `0x461237c` |
| Message | `+0xF8` | 服务器消息 ID | `0x457b900` |
| Message | `+0x130` | 正文 | `0x4666a3c`、`0x4543f50` |
| Message | `+0x100` / `+0x114` | 排序号 / 时间（秒） | `0x4611d34`、`0x4611d40` |
| Message | `+0x258` | 是否已终结 | `0x4612e90` |
| 撤回对象 | `+0x1A8` | 类型串 `revokemsg` | `0x4666e90` |
| 撤回对象 | `+0x1C8` / `+0x1D0` | `newmsgid` / 提示文案 | `0x4667638`、`0x46676cc` |

字符串都是系统 libc++ 的 `std::string`，微信与模块共用同一份 libc++。

## 模块做了什么

1. 微信加载 `wechat.dylib` 时，核对 LC_UUID 和两处跳转字节，都符合才写入函数指针。
2. 终结器之后：按「服务器 ID → 类型 + 摘要」记进内存，最多 10000 条，文字最多 100 字。
3. 解析函数之后：从 XML 里取 `newmsgid` 查表，查到就改写 `+0x1d0`。自己撤回的不改。

4. 通知成型后：把撤回通知的时间和排序号换成原消息的，让提示排在原消息下面（见下）。

### 提示的位置

`newmsgid` 清零后，微信走「没找到原消息」的分支（`0x3135fcc`）：新建一条系统消息，时间 `+0x114` 和排序号 `+0x100`
直接抄自撤回通知，于是提示落在撤回那一刻。排序号 = 时间 × 1000 + 同一秒内的序号，插入时不会重算。

所以模块在终结器之后，把撤回通知的时间改成原消息的时间，排序号改成 `时间 × 1000 + 999`：一定排在原消息之后、
下一秒的消息之前。查不到原消息、时间倒挂、相隔超过 7 天时不动。

摘要会去掉换行、控制字符和零宽字符，`<` `>` 换成全角，避免被当成标记。日志只有计数，没有聊天内容：

```bash
/usr/bin/log show --last 10m --predicate 'subsystem == "wxar.tip"'
```

`active` 表示已启用；`revoke hit=1 changed=1` 表示查到原消息并改写了提示；`moved back N s` 表示提示往回挪了 N 秒。

## 已知限制

- 只认本次启动后收到或加载过的消息。
- 同一秒内连发多条时，提示排在这一秒的最后一条下面。
- 沙盒版（App Store）重签名后，系统会拒绝它访问腾讯的 app group 容器。
